## 結論

**建てる。`D:\work8\Laterna\imagegen\` に、ComfyUI_img2 の型をそのまま借りた 1 インスタンスの ComfyUI 環境を置く。**
img2 は呼ばない（imagegen が 9/29 までに動かないときだけ、brief §9 の D8 訂正の経路で呼ぶ）。

理由は 3 つ。

1. brief D8 の狙い（img2 に他プロジェクトの要求を持ち込まない・境目を曖昧にしない）は、Laterna が自分の環境を持てば完全に満たせる。D8 訂正（img2 の例外）は要らなくなる。
2. 公開して実績にする（主人）なら、動画の作り方が 1 つのリポジトリで再現できる方がよい。img2 は private リポジトリで、外から見えない。
3. 主人が時間・トークンの制約を外した。10/1 の期限は、立ち絵の予備（既存の 2 枚）と img2 の予備経路があるので守れる。

## brief §6 の 5 問への答え

| 問い | 答え | 根拠 |
|---|---|---|
| 置き場所 | `imagegen/`（Laterna の中）。git で追跡するのは `scripts/`・`versions/`・`workflows/`・`README.md` だけ。`ComfyUI/`・`.venv/`・`python/`・`models/`・`output/`・`runtime/`・`logs/`・`.cache/` は `.gitignore` | img2 と同じ構成（`versions/` で版を固定、重みと本体は入れない） |
| 使うモデル | **FLUX.2 [klein] 4B fp8**（text-to-image と参照画像つき編集の両方）＋ text encoder `qwen_3_4b` ＋ `flux2-vae`。3 本で 12.4 GB。すべて Apache-2.0（img2 の `versions/models.json` に sha256・取得元・ライセンスが記録済み） | 立ち絵の原画と差分（口・目）が同じモデルで作れる（研究資料 §6）。商用可（研究資料 §8） |
| See-Through と派生 | **採らない。**口・目の差分は klein の参照画像編集で作り、変わった部分だけ ImageMagick で元絵に貼り戻す（研究資料 §5〜§7） | カスタムノードが要らない。動かすのは Remotion 側（brief §7-2） |
| GPU の割り当て | 1 インスタンス。`--cuda-device` は起動引数で選ぶ（既定 1）。port は **8288**（img2 の 8188／8189 と衝突しない） | klein 4B fp8 ＋ qwen 3 4B ≈ 12 GB。16 GB の GPU に 2 つは載らないので、img2 と同じ GPU では同時に動かさない（README に書く） |
| モデルファイルを img2 と共有するか | **共有しない。コピーする。**`versions/models.json` に同じ sha256 を書き、setup が検証する | 共有すると img2 側の更新で壊れうる（brief §6）。ディスクは 980 GB 空いている |

## 借りる型（`D:\ComfyUI_img2`、読み取り専用）

| img2 の物 | imagegen での扱い |
|---|---|
| `scripts/setup.ps1`（uv で Python 3.13.15 を固定、venv、ComfyUI を tag で clone、`requirements.lock` と sync、モデルを sha256 で検証。冪等） | ほぼそのまま。取得元をコピー元（`D:\ComfyUI_img2\models\...`）にも対応させる（無ければ HF から取る） |
| `scripts/start.ps1`／`stop.ps1`（ポートの所有者を確かめ、自分の物だけ止める。127.0.0.1 だけで待ち受け） | 1 インスタンス版に縮める。port 8288、`--cuda-device` を引数に |
| `scripts/smoke.py`（標準ライブラリだけの HTTP クライアント。POST /prompt → /history → /view） | t2i と edit の 2 本に縮める。同じ `build()`／`run()` を `gen.py`（立ち絵生成の作業スクリプト）から使う |
| `workflows/klein_t2i.json`・`klein_edit.json`・`inject.json` | そのまま借りる（API 形式。差し込み位置の表も） |
| `versions/comfyui.txt`（v0.37.0）・`python.txt`（3.13.15）・`requirements.lock`（86 行）・`models.json` | klein 4B の 3 本だけに絞って借りる |
| `ui/`・`img2client/`・`verify.py`・`bench*.py` | 借りない（UI と検証台は器。Laterna には要らない） |

**カスタムノードは 0 本で始める。**足すときは `versions/custom_nodes.json`（リポジトリ URL・commit）で固定する。img2 と違って足すことを禁じない ── それが専用環境の意味。

## 費用の見積もり（実測ではない）

- セットアップ：30〜60 分。uv の Python 取得、torch cu130（約 3 GB）、ComfyUI clone、モデルのコピー 12.4 GB。
- ディスク：約 20 GB（`.venv` 6 GB・モデル 12.4 GB・ComfyUI と cache）。
- 生成：klein 4B fp8 で 1024×1024 が数秒〜十数秒／枚（img2 の実測は `verify-report.json` にある。読んで確かめる）。

## 採らなかった案

| 案 | 却下理由 |
|---|---|
| img2 をそのまま使い続ける（D8 訂正の経路） | 公開リポジトリから再現できない。img2 に要求が積もる（D8 の懸念）。ただし **予備経路として残す** |
| `D:\work8\Laterna-imagegen`（別リポジトリ） | 主人の指示は「プロジェクト内部」。別にする理由（別の主人・別のライフサイクル）が無い |
| Z-Image Turbo も入れる | 1 本目に写実の挿絵は無い（D9）。要るときに `models.json` に足す（戻す条件） |
| Laterna の compile 段から imagegen を呼ぶ（D10） | 立ち絵は台本を跨ぐ素材で、compile 段の生成対象ではない。挿絵を入れる Wave（2 本目以降）で設計する |
